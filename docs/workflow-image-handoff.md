# fal / Replicate 图片结果原生接管（代码阶段）

`designcraft_fal_workflow` 和 `designcraft_replicate_workflow` 保留既有模型发现、显式远端任务、查询及恢复。新增 `prepare_image` 通过明确的任务 ID 和结果 JSON 指针，登记该任务实际返回并保存的单张图片；`images` 列出已登记来源和待核对导入，`recover_image` 仅恢复完整的本地临时来源记录。专业图片工作区的“外部工作流图片”面板也可查看已保存输出并登记来源。

来源检查要求任务已记录服务完成、结果摘要一致，输出指针对应的项目素材、实际字节数及 SHA-256 全部一致。`open_image` 以稳定身份将已登记原件导入独立 PhotoCraft 图片源；`reconcile_image` 只核对已有操作、原始图片和已保存原生源，不重新请求服务或重复导入。项目包保存并核对工作流任务、图片来源、导入预约、原件与原生关联。输出与任务的对应关系来自当时的服务响应，并非本机可独立验证的服务端签名。

当前原生接管仅支持不超过 16 MiB、内容实际为 PNG/JPEG 且尺寸满足现有图片引擎预算的输出；WebP、视频、音频和其他文件仍保留为项目素材，但该入口不会把它们当作原生图片导入。图片导入不会恢复矢量路径、原始图层、文字或模型的内部生成过程；实际外观和可编辑性仍须验证。

本轮只写入代码并做静态检查，没有调用 fal 或 Replicate、生成或下载图片、运行导入/UI/恢复/项目包功能验证，也没有操作或重启用户 DSH。相关服务、账户和模型能力均以实际运行结果为准。
