# OpenDesign 外部原包文件的原生导入（代码阶段）

外部技能原包需先通过 `designcraft_resources` 的 `external_discover`、`external_inspect` 和 `external_fetch` 固定并保存；再用 `external_materialize` 保存实际文件，或在 Git LFS 指针时用 `external_lfs` 按指针核对并保存实际文件。网页资源面板也提供相同的选择与保存入口。获取原包或 LFS 文件依赖网络；此功能不会执行原包脚本。

对已经物化的 `externalfile-…` 或 `externallfs-…` 来源，`external_open` 使用明确的 `kind=svg`、`kind=image` 或 `kind=deck` 和稳定操作身份，复查保存的原包、Git blob/LFS 指针、原文件大小与 SHA-256，再将 SVG 交给 VectorCraft、PNG/JPEG 交给 PhotoCraft、PPTX/POTX/PPSX 交给 DeckCraft，作为独立原生源。网页面板可对所选受支持文件先保存原件再打开。SVG 要通过静态安全检查、不得包含外部引用或脚本，最大 8 MiB；图片和演示原件最大 16 MiB，尺寸还受现有图片引擎限制。演示包只做有界 ZIP 结构和必要条目检查，实际导入由 DeckCraft 处理。外部文件不因改扩展名而自动成为可编辑对象；字体、位图、复杂效果和视觉保真仍需实际核对。

演示包准入最多检查 10,000 个 ZIP 条目，单项声明解压大小不超过 32 MiB，总声明解压大小不超过 128 MiB；两个必要 XML 条目各不超过 2 MiB 并核对其 CRC。超出这些限制的文件会被拒绝，原件仍保留；这不是对整个文件所有内容的完整验证。

导入前保留稳定预约，保存原生源后记录原件、源修订和来源关联。`external_opens` 列出预约和仅通过结构检查的临时记录；`external_recover_open` 只在来源与所需原生证据核对后恢复本地预约或结果回执，不执行导入；`external_reconcile` 使用已有回执或操作及源版本核对，不重新下载或重复导入。新导入的 SVG、图片和演示首次源保存回执会记录稳定预约身份：操作日志缺失时，只有实际已保存源、原件摘要和预约身份唯一匹配，才恢复关联；否则保持未确认。此前没有该身份的 SVG/图片旧源不会仅凭相同哈希猜测来源。 从操作日志恢复时，结果发布前还要核对已保存源的动作、资源、输入摘要和预约身份；新发起的导入要求源回执确实含有匹配的预约身份。网页面板保留上次未确认操作的身份，要求先核对或由用户明确停止等待。项目包保留并核对原包、许可文件、原件、预约、结果回执和已保存原生源；没有结果回执的预约仍按未确认保留。

工作区面板发起的外部原生导入记录为手工操作；同一 DSH 对话通过工具发起的导入记录为 AI 操作。此区分不证明文件解析或视觉效果，相关新路径尚未验证。

上游仓库和文件的许可证、署名及第三方素材权利以原包及实际许可为准；文件单独导出时不会自动附带全部许可。Git 对象与已保存包可做本地摘要核对，线上仓库对应关系来自获取时 HTTPS 响应，不是独立签名证明。

本轮只写入代码并做静态检查；外部 PPTX/POTX/PPSX 的来源、导入、保存、恢复和项目包链路尚未进行功能验证。没有下载外部原包或 LFS、执行上游脚本、运行原生导入/UI/恢复/项目包功能验证，也未操作或重启用户 DSH。
