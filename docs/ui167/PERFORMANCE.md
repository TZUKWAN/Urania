# UI167 流式对话性能

同一 Windows 机器、独立 DSH 0.2.2-rc.1、无窗口 Chromium、1440×900、同一矢量画布和中文 Markdown 写作需求。每次发送都经过真实 DSH 会话。UI167 各轮回执显示 `glm-5.3-flash`。UI166 基线留下了实际消息和渲染事件，模型字段取样时还没有值。

通过 `requestAnimationFrame` 记录帧间隔，只统计靠近实际文本 DOM 更新的帧。各轮模型返回长度和节奏不同。Chrome 主线程事件同时保留经过时间与线程 CPU 时间。

| 构建及处理 | 活跃帧 | P95 | P99 | 最长 |
| --- | ---: | ---: | ---: | ---: |
| UI166 独立基线 | 1,531 | 16.8 ms | 33.4 ms | 133.3 ms |
| UI167 首次复现 | 1,026 | 50.0 ms | 83.3 ms | 350.0 ms |
| UI167 补录诊断轨迹 | 1,150 | 33.3 ms | 33.4 ms | 266.6 ms |
| UI167 隔离消息流布局及精简文字动效 | 1,258 | 33.3 ms | 50.0 ms | 216.7 ms |
| UI167 使用静态运行图标 | 910 | 50.1 ms | 83.3 ms | 333.2 ms |
| UI167 发布候选，增加滚动视口隔离 | 1,145 | 33.4 ms | 66.7 ms | 466.6 ms |

最初出现 50 ms 的候选轮保留了帧样本和长任务记录，该轮的 Chrome 轨迹流未导出。其余五轮保留了 Chrome 轨迹。

- 补录轨迹中，DSH 前端 React 回调占约 1.38 秒经过时间，主文档触发 1,367 次布局，左侧树也出现在 1,323 次绘制事件里。从 UI166 到这轮 UI167，Urania 原生控制器定时回调的总经过时间从 104.37 ms 降至 42.50 ms，单次最大值从 36.52 ms 降至 3.31 ms。不同轮的采样时长和响应节奏不同。
- 使用静态运行图标后仍出现一个 127.15 ms 的主线程任务，其中记录到 22.29 ms 线程 CPU 时间。任务内部一条 69.69 ms 布局事件记录了约 6.02 ms 线程 CPU 时间。由此可见，在这些长事件中，线程运行以外的等待同样明显。现有数据无法把这部分等待唯一归因给具体进程或设备。
- 发布候选将 Urania 会话外壳的订阅缩小到当前范围和运行状态，保持 DSH 会话节点稳定，将对话滚动与设计画布的定位分离，隔离消息滚动视口。运行行保留状态文本、用时和静态图标。最终一次实测的 P95 低于最早复现的 50.0 ms，长尾仍存在，稳定的 60 Hz 流式表现尚未验收。
